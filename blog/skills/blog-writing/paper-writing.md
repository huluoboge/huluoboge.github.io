# 论文解读与综述细则

默认读者是有相关技术背景、尚未读过当前论文的同行。目标是让他们准确、顺畅地理解论文，篇幅以讲清楚为准，不追求缩短文章。以准确理解论文为基础，用自然中文转述其论证，并融入有依据的分析、推导与理解。单篇论文解读原则上沿原论文的论证顺序展开，在理解有跳步的地方直接讲清关系，不把文章机械地分成翻译和补充解释两层。用户明确指定节选、解读或综述时，按指定范围与形式执行。

多篇论文综述围绕共同问题组织，比较维度从所选论文中提炼，并分别保留各论文的前提、证据和结论强弱。单篇论文的章节顺序要求不用于多篇综述。

已有博客只在术语或系列背景确实相关时选读，不充当当前论文的内容或结构模板。

## 先完整理解原文

开始论文解读前，必须下载指定版本的原论文 PDF 到临时目录，并验证文件确为完整、可读取的 PDF（例如用 `pdfinfo` 检查页数，并成功提取文本）。不得仅凭网页摘要、HTML 转换页、搜索摘要或论文 PDF 链接代替下载和读取 PDF。PDF 同时包含补充材料时，应一并阅读；若补充材料单独提供，也应下载并验证。

若 PDF 下载失败、文件不完整、格式无效或无法读取，立即停止该论文解读任务：不得新建或修改文章正文、不得把远程图片链接当作本地论文配图的替代品，也不得运行博客构建。向用户报告具体失败步骤和错误，等待网络或来源恢复后再继续。临时 PDF 不提交到仓库。

PDF 验证通过后，通读原论文全文，包括图表、图注，以及承载方法、训练或实验细节的附录。确认使用的版本，记录论文页面与 PDF 链接。正文引用或讨论论文中的图表时，必须以论文原图为准：从论文 PDF 或来源文件提取原图，保存到文章目录的 `figures/`，检查裁切完整、网页宽度下可读，并确保 Markdown 引用指向本地图片。自绘图可以额外补充，用于解释原图难以表达的步骤、因果或细节，但必须明确标注为自绘，并与原图并列或放在原图之后；不得以自绘图、重绘版、截图式文字描述或 PDF 页码链接代替相关原图。若确实无法取得或提取相关原图，说明具体图号、尝试过的来源与障碍，并将其列为未解决缺口；在获得原图前，不得把文章标记为完成或通过最终清单。

阅读时梳理作者的问题、定义、假设、计算过程与证据，弄清段落之间的承接关系。建立术语和符号的一致约定，并记录需要补充解释的具体位置。正式写作前确定覆盖范围；长文可以分批处理，但保留尚未完成的部分，最终核对覆盖情况。

## 准确、自然地讲清论文

- **信**：保留原文的含义、论证关系、定义、公式、实验数据、假设与限定，准确表达结论的强弱。区分假设、经验观察、实验结论和理论保证。关键主张应能追溯到原文，局部调整表达时保持论证关系，不删去必要条件或混淆不同主张。
- **达**：按自然中文表达，允许拆分长句、调整句内语序、补出中文必需且指代明确的主语。写清代词指向和连接关系，避免逐词对应的翻译腔；调整表达时保持原意与因果方向。
- **雅**：使用准确、平实、流畅的技术语言。术语稳定，句子读得顺；不为追求文采添加修饰、比喻、口号或原文没有的评价。

单篇论文解读保留原论文的章节顺序和论证层次，章节标题准确表达原意；多篇综述按共同问题组织，并在论述各论文时保留其前提与推理关系。论文、书籍等作品名称保留原文。准确覆盖所讨论的摘要、正文、图表及图注，附录中承载关键细节的部分应一并说明。参考文献条目可以保留原文。公式保留原符号与编号，文中的图、表、章节引用应能在文章或明确链接的原文中找到对应位置。

网络结构、原始定义、目标函数和实验比较按原文准确呈现，不能用直觉说明替代。发现原文疑似笔误、符号不一致或表述歧义时，保留可追溯的原文信息，在相关位置说明所采用的理解及依据；不静默修正成自己的版本。

## 将解释自然融入论述

以独立解读者的口吻写作，不沿用论文作者的“我们”“我们的模型”等第一人称。根据语义使用“作者”“论文”“该方法”“模型”，或直接陈述计算与结果；不要把每个“我们”机械替换成“作者”，导致句句重复主语。涉及作者的判断或推测时明确归属，避免将其写成已证实的事实。

解释紧接相关段落或公式，直接展开背景、中间步骤和机制联系。通常写成自然段；需要与主线区分的推导、理解或原文歧义，可以使用 Markdown 引文块 `>`。不加固定的“补充解释”“推导补充”“译注”标签，也不反复提醒哪些段落来自翻译。较长解释可用具体内容作小节标题。论文结论、代码细节和自己的推断仍需通过措辞与来源交代清楚，不把猜测混成作者的结论。

按实际难点选择补充内容：

- **背景和对象**：解释当前理解所必需的概念、输入输出、符号、坐标系或量纲。对同行已熟悉的常识按需简述，重点展开论文特有的对象及关系。
- **推导步骤**：补出公式之间省略的代入、变换、近似或成立条件。说明这一步用到了什么，结果为何成立，后续怎样使用。省略步骤需要实际展开，复述结论不能替代推导。
- **机制联系**：讲清前一步产生什么、下一步如何使用。缓存说明保存与复用的对象，注意力说明读取范围与更新关系，坐标变换说明参考系和方向。训练说明标签、预测与损失的联系，实验说明指标、比较条件以及结果所支持的判断。
- **阶段总结**：在较长论证之后收拢已经建立的关系，帮助读者继续阅读。总结不引入未经解释的新结论，也不以重复结论代替缺失的机制说明。

补充推导要检查数学与适用条件；补充背景尽量使用可靠来源并给出链接。原文没有交代的设计动机，若给出合理解释，用“可以理解为”“这里推测”等自然措辞说明其不确定性；无法确定的地方保留不确定性，不替作者补造事实。官方代码可补充实现细节，标明来源及版本，区分论文描述与实现。

### 例子与表达

例子按具体难点选用，可以不用，也可以局部使用。只有同一组输入确实能帮助解释连续变化时才贯穿；几何、训练与实验各自采用合适的说明方式。简化例子保留所讲机制成立的条件，不虚构网络执行了匹配、三角化或优化等步骤，不把特征传播写成可追踪的物理点运动。

正面交代用途与假设，例如“为了说明逐帧更新，下面以三张依次到达的照片为例”或“下面用一组便于手算的假设分数说明分配过程”。用途和来源已清楚时，省去重复的“不是论文实验”等声明。否定句用于澄清具体误解，随后给出成立的关系或原因；自行撰写的解释避免反复用辩驳句式推进。

解释使用自然段，先讲清一个关系，再补细节。发现段落同时引入过多新对象、公式和边界条件时，拆开并补上承接。图示和局部演算用于解决具体理解困难，增加篇幅应带来实际解释。

单篇论文解读标题采用“论文名或简称＋论文解读”，例如“VGGT-Long 论文解读”；多篇综述标题准确说明共同主题，不套用单篇论文标题格式。不使用“论文翻译”“译文”或“翻译与补充解释”作为文章名。front matter 的 `title` 与正文一级标题保持一致，摘要及导言准确介绍文章范围；正文仍按上述要求忠实转述来源并补充解释。

标题已说明是论文解读时，导言直接进入论文主题，不重复解释文章形式。避免“本文不作全文翻译”“不完整复刻图表和参考文献”“自行补充内容将用某标签标明”等写作声明。补充说明在相关位置自然出现；具体来源缺口和歧义也在影响理解的位置交代，不堆成开头或结尾的范围免责声明。

## 写完必须自己 review 并修订

完成初稿后，由写作者实际执行以下三轮检查，发现问题就修改对应段落，修改后重新核对受影响的内容。检查过程用于改稿，无需把内部清单写进正文。

### 第一轮：对照原文检查准确性与完整性

逐节逐段对照声明范围内的原文，检查遗漏、误解、指代、否定、比较关系、因果方向、结论强弱和限定条件。核对公式、下标、坐标方向、图表编号、实验数字、单位及评价协议。检查段落是否仍保留原来的推理关系，论文结论与自己的解释、推断是否能清楚区分。发现错误先修正，再回看关联段落、公式与引用。

### 第二轮：只读中文检查表达

暂时放下原文，连续通读中文。检查是否存在生硬语序、超长句、含混指代、术语漂移和断裂的段落衔接。自然语言应能直接理解，避免要求读者先在脑中还原英文。逐处改写不通顺的句子，再对照原文确认没有改变含义；不能为了顺口删掉技术条件。

### 第三轮：按目标读者检查理解

暂时不借助原文，只凭文章，尝试复述问题、核心思路、关键计算、训练方式与实验结论。对每个重要推理衔接具体检查：目前已知什么，接着求什么，为什么可以这样求，结果怎样被使用？遇到必须猜测、回翻多个定义或自行补推导的位置，定位缺口，在相关位置补充解释。

尤其检查：是否只是换句话重复模块名；是否列出了公式却没解释它的工作；是否用总结代替展开；例子是否真正解释了难点。解释不清就重写或补足，篇幅可以增加。新增解释再经过准确性与中文表达检查，避免改稿引入新的错误。

完成标准是三方面同时满足：忠于原文、中文通顺、关键推理可以跟上。不能把“格式正确”“细节齐全”或“通读过一遍”当作通过 review。对尚未解决的来源缺口、歧义或推导问题，在交付时说明具体位置及影响，不声称已经确认。

## 在本仓库落稿

新文章放在 `blog/articles/<slug>/index.md`，图放在同目录的 `figures/`。沿用博客 front matter，按本博客本地 review 的约定设置 `draft: false`；发布操作按用户要求与仓库流程执行。

单篇论文解读在标题后、正文前保留一段简短的 Markdown 引文块，介绍论文主题，注明论文题目、作者、版本及论文页面与 PDF 链接。作者较多时可用“等”简写。多篇综述则在导言或参考资料中明确列出所讨论论文及版本，不强制使用单篇论文引文块。标题已交代的文章形式无需重述；只有节选范围会影响理解时才补一句具体范围。不要预告注释标签或罗列省略的内容；单篇解读不另造贯穿场景或重组原文主线。

正文讨论或引用到的原论文图表必须实际嵌入原图，在图注标明原图号；PDF 链接只能作为来源，不能替代嵌入。必要时可在原图旁增加中文标注或单独的自绘解释图，但自绘内容是补充，不能取代、裁切到改变含义或掩盖原图。核对原图裁切完整、网页宽度下可读、所有文件路径有效；自绘图标明用途，避免与论文原图混淆。

相关文章确实能提供背景时，自然交代关系并链接到已存在的文章；避免插入无关的系列叙述。结束前核对引用、图片路径与覆盖范围，报告 review 中修正的主要问题及仍存疑之处。按仓库要求构建文章；下载的论文 PDF 不提交。

## 最后一步：交付前核对清单

文章、图片和引用都改完后，交付前必须逐项执行以下检查。它是最终门槛，不用构建成功、写作过程中的印象或此前某一轮 review 代替。发现问题就先修改，并重新检查受影响的条目；确实无法解决的项目，交付时说明具体缺口、原因和对理解的影响，不得默认为通过。清单供写作者自检，不复制到博客正文。

- [ ] **原文与范围**：确认论文版本、作者、论文页面和 PDF；全文、图表图注及承载关键细节的补充材料已读完。声明范围内的章节、实验和结论均有覆盖；读不到的内容已明确标出。
- [ ] **引文与来源**：单篇论文的标题、作者、版本、论文页和 PDF 链接均已写在标题后的引文块中。关键主张、数字和补充背景能追溯到原文或明确标注的可靠来源。
- [ ] **原图与自绘图**：正文实际嵌入了所有被讨论或引用的相关原论文图表，图注标明原图号；裁切完整、缩放后可读、图片路径有效。PDF 页码链接不能算作已嵌入原图。若添加自绘图，它只能补充原图的解释，已明确标注用途，且没有替代、重绘或掩盖原图。若确实无法取得或呈现相关原图，列为未解决缺口，说明具体图号、尝试过的来源、障碍和对理解的影响；不得勾选通过或宣称文章完成。
- [ ] **公式与术语**：对照原文核对公式编号、符号、上下标、坐标系、单位、变量定义、假设和成立条件；公式前后解释了计算对象、结果及其后续用途。没有把推测写成论文结论。
- [ ] **实验与结论**：逐项核对数据集、指标、数值、单位、比较对象、评价协议和论文限定；区分作者报告、经验观察与本文推断，没有把不同系统变体或不同实验条件混在一起。
- [ ] **三轮 review 已真实执行**：第一轮逐段对照来源检查准确性和完整性；第二轮脱离来源连续通读中文；第三轮只凭文章检查读者能否复述问题、关键机制、计算关系和实验结论。每轮发现的问题都已修复，受影响内容已回查。
- [ ] **成品链接与构建**：检查文章内链、外链、图片路径和生成页面；按仓库要求完成构建。构建成功只说明生成流程完成，不代表内容 review 自动通过。
- [ ] **改动与交付说明**：核对 git status --short，只报告与本任务有关的改动；交付时简要说明 review 中实际修正的主要问题，以及尚未解决的来源缺口或歧义。
