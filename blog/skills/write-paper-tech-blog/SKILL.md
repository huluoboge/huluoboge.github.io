# 论文技术博客写作

这份 Skill 记录本博客对论文解读的要求。写作先读懂当前论文，不设固定范文必读。已有文章只在与主题、系列背景或术语衔接确实相关时选读；它们可以帮助保持站内叙述连贯，不能替代原论文，也不能决定新文章的中心思想、章节或篇幅。

## 找到文章要解释的事

先通读原论文全文，包括正文各节、图表及图注；方法细节、训练或实现条件落在附录时，还要读对应附录。不要只凭摘要、引言或结论写稿。阅读时逐节记录：作者在这一节回答什么问题，给出了哪些定义和假设，指出了什么困难，提出什么思路，具体怎样计算或实现，拿什么实验或论证支持。区分作者的核心信息与背景、延伸讨论，确保每一节的关键内容在成稿中都有去处。

再从这些记录中提炼文章主线：作者到底要解决什么问题，原有做法卡在哪里，如何定义任务与输入输出，方法为什么这样设计，各模块怎样接起来，实验能证明什么。博客可以按读者理解所需的因果顺序重组论文，不必照搬目录；但重组后仍要逐节回查，不能让原文的关键定义、机制或限定条件在改写中消失。若只讨论论文的一部分，应在开篇说明范围，而不让读者误以为已经覆盖全文。

阅读记录不能停在摘录结论。对论文中每个承载关键论证的段落，想清楚它接续了前面哪个问题、作者为何引入这个设计或实验、做法与旧方法的具体差异、付出的代价，以及下一段如何使用这个结果。先把这些关系串成论文的中心思想，再动笔写博客。原文没有说明的动机不要替作者编造；自己的机制推断须明确标出。

用一句话写出文章主线，再为每一段确定它要回答的读者疑问。这个提纲只用于组织写作；正文自然地推进，不出现“立意分析”“本段思想”“段落拆解”等讲义标签。

标题后、正文开篇前必须放置一段 Markdown 引文块（以 `>` 开头），概括文章的主要内容、展开主线和讨论范围。读者应能先通过这段话知道本文要讲什么、哪些内容会简述或留待另文；不能只写论文元信息来代替内容提要。基于论文的文章可在引文块中同时标明作者、年份和论文题目。

引文块之后，正文开头从可想象的场景或实际工程后果进入问题，随后交代方法在完整系统中的位置。让读者先知道为什么需要这个设计，再看模块和公式。引文块是本博客文章的固定组成部分，但不要求复用某一种固定措辞或篇幅。

## 沿着因果链讲方法

- 按“现有信息不足在哪里 → 新增什么信息或约束 → 怎样计算 → 得到什么能力”的顺序展开。标题写具体问题或机制，避免把论文目录直接改写成中文目录。
- 遇到抽象概念，先给一个足够小、可手算或可想象的例子；明确它是讲解用例，还是论文报告的实验。例子不能替代真实方法的条件。
- 公式出现时就解释变量、坐标系、量纲或约束的作用；推导只保留能让关键跳步变得可理解的步骤。解释公式为什么这样写，以及它不能保证什么。
- 对理解方法必需的原文定义、矩阵、目标函数和结构差异，先准确给出，再解释它们的意义与计算过程。不能用直觉比喻、缩写公式或演算例子替代原定义；论文明确指出的关键设计（例如某一步计算哪些投影、不计算哪些投影）要直接写出来。
- 每讲一个方法选择，都回答“为什么在这里需要它”：先说明现有方案的具体开销或失败点，再说明作者改了哪一步，如何影响训练、推理或结果。不能只罗列模块、公式与效果，让读者自己回论文寻找因果关系。
- 区分论文明确给出的结论、由公式直接推出的性质，以及作者自己的机制解释或推测。发现原文符号不一致或适用条件有限时，写明所采用的约定和边界。
- 用连续段落写文章。列表和表格用于真正需要比较的地方，不把每段压成“目标／已知／收束”式提纲。

以没读过论文的读者检验正文：只看这篇博客，能否说清作者的问题与任务定义、先前困境、解决思路、关键计算步骤、各模块的作用和实验结论？如果理解某个核心设计仍须打开论文找缺失的公式、矩阵、条件或一句关键说明，就继续补正文。参考文献用于溯源，不能代替文章自身的解释。

### 独立阅读要能跟着一次输入走到底

对系统类论文，选一个足够小且贯穿全文的输入例子（如三个时刻、两台相机或几个点），从原始输入一路跟到输出。每经过一个模块，都写清它**收到什么、利用了什么先前未知的信息、输出的对象是什么、下一步怎样使用**。对象从图像变成特征、从特征变成缓存、从缓存变成位姿时，不能只换术语而跳过转换。讲解用例与论文真实实验分开标明；例子可以简化数值，不能暗示论文执行了不存在的算法步骤。

结构图可以早放，尤其当它帮助读者建立路线；放图前先给读者足够的对象和读图顺序，放图后用同一个例子逐块兑现。原图上有英文缩写、细小标注或多条支路时，图注不能只把框名翻译一遍。至少说明入口、出口、信息流向及当下要看的部分；后文回指图中的具体节点。不要靠“图中符号下文解释”代替当前必要的导览。

对缓存、注意力掩码、坐标变换等机制，写一遍**最小运行过程**：先到什么，保存什么；下一次到来时重新计算什么、直接复用什么；某个输出依赖哪些历史，不能依赖哪些未来。若公式中出现集合、指示数、维度或坐标下标，紧挨公式用这一过程解释其取值和方向。对于多层注意力，区分同一层读取上一层状态与跨层信息传播；不要用“互相交换”掩盖时序约束。

区分“为了说明标定或几何而写的解释式”与“论文网络实际执行的运算”。解释式必须明确它能确定什么、仍未知什么；不能让读者误以为模型显式做了三角化、匹配、优化或其他论文没有声称的步骤。黑箱预训练模块不必展开其训练史，但必须交代本方法给它什么输入、得到什么输出、为何这些输出足以供下一步使用，以及这个判断的证据边界。

训练部分用同一个例子接上推理过程：标签从哪里来，哪个预测与哪个标签比较，分阶段时每阶段的输入、可见范围、受监督目标及继承的参数各是什么。损失先给一个可手算的误差场景，再给公式和每一项的作用。实验先用一句人话解释指标的单位与大小，再按“要验证的设计 → 尽量受控的比较 → 数字 → 能支持和不能支持的结论”来写；跨数据集、尺度对齐或训练预算不同时不强作单因素归因。

落稿后做一次不打开论文的复述检查：遮住模块名和公式，只读正文，能否沿同一个例子说出每一步的输入、输出、缓存、坐标系、训练标签和实验所支持的结论？再反向核对原论文，确保为填补叙述跳步而加入的推断、简化例子和直观量级没有被写成论文事实。读不通时先补桥梁、重排顺序，不能靠删公式、加术语表或增加空泛总结蒙混过关。

## 让系列文章彼此衔接

如果新文章属于已有系列，先检查仓库中的相关文章，确认哪些内容已经讲过、当前文章准备深入哪一部分。正文前部应使用站内链接引用最相关的前文，并用自然段说明两篇文章的关系：前文提供什么背景，本文承接或补充什么。只链接实际存在且与当前主题相关的文章，不虚构篇名、链接或尚未发布的后续内容。需要引用多篇前文时，分别说明它们与当前主题的联系，避免堆放无说明的“相关阅读”链接。

若后续文章已经存在，可从当前文章链接到它；若系列仍在撰写中，只建立指向已发布或已落稿文章的链接，不预设未完成文章的路径。站内链接沿用仓库现有相对链接格式，并在落稿检查中确认目标有效。

## 让图和实验承担证据

在架构、注意力、输出效果等关键处，优先选原论文中真正帮助理解的图。可以从论文 PDF 截取原图，存入该文章的 `figures/`，确认裁切没有截断标注、图像在网页宽度下可读，并在图注写清原论文图号、图中对象以及要读出的信息。自绘图适合补足原图没有说明的关系。不要把一页论文截图堆到文章末尾。

训练是方法的一部分，不能只用“在某数据集上训练”带过。说明监督标签从哪里来、正负样本怎样定义、目标函数怎样作用于各模块、是否分阶段训练或冻结梯度；预训练、微调和关键实现设置若影响论文主张，也要交代清楚。让读者能够沿着“数据与标签 → 损失 → 被训练的预测 → 推理时的用途”复述训练过程。

实验段落先说明数据、评价指标、比较对象与受控条件，再给有辨识度的数值或图。解释这个实验究竟支持了哪一项主张：整体效果、下游任务收益，还是某个模块的贡献。比较不同前端、训练设置或评估协议时，指出归因限制；定性图展示现象，消融表帮助解释原因，不用单个好看的案例代替总体证据。

逐项核对论文的主实验、消融与训练曲线：点数、图像尺寸、阈值、硬件、计时范围及误差指标是否影响比较；哪些结论由数据直接支持，哪些只是合理解释。结果有取舍时如实写出，不把单项胜出概括成全面更优。方法中的每个重要设计最好能在实验或消融中找到对应证据，也要说明证据覆盖不到的场景。

收尾回到论文的核心认识和适用边界，例如对前端质量、场景分布或后端几何验证的依赖。参考资料提供能打开的论文页面及必要的 PDF 链接；正文中的数字、图和特殊判断要能追溯到原文。

## 在本仓库落稿

新文章放在 `blog/articles/<slug>/index.md`，图放在同目录的 `figures/`。沿用博客 front matter，写作阶段保留 `draft: true`；用户要求发表时改为 `false`，按仓库现有构建与发布流程执行。写完通读一遍：删掉读者还没获得上下文就出现的术语，检查相邻段落是否在推进同一条主线，并核对所有图片路径和参考链接。最后按阅读记录逐节核对论文：中心思想是否贯穿全文，每项关键设计的“为什么”是否讲清，方法、训练和实验细节是否准确落稿；再做一次不翻原文的独立阅读检查。
